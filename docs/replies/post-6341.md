# dsh 在 Node < 22.18 上静默失效：CLI 入口被 import.meta.main 门控（所有命令无输出、退出码 0）

Status: **POSTED** (user-approved, standalone) — https://github.com/deepseek-ai/deepseek-harness/discussions/6341

---

> **EN TL;DR** — On Node < 22.18 (all of Node 20, 22.0–22.17, and 23.x), **every** `dsh` invocation prints nothing and exits 0. The CLI entry is gated by `if (import.meta.main) await runCli();`, and `import.meta.main` only exists from Node **v22.18.0** / **v24.2.0** upwards. The published package has no `engines` field, so npm neither warns nor refuses. Fix: run on Node 22.18+ or 24+.

## 症状

`npm install -g @deepseek-ai/dsh` 安装成功，但之后任何命令都**零输出**：

```
$ node -v
v22.17.0
$ dsh --version          # 无输出，立即返回提示符
$ echo $?
0
$ dsh web                # 同样无输出
```

**关键判据**：连 `--version` 都静默。node-pty 缺失、`.env` 被建成目录、端口占用、bundle/patch 问题都会打印错误或堆栈——**只有 CLI 入口根本没执行**，才会连 `--version` 都零输出。Windows(cmd) 与 zsh 上表现一致，与安装是否完整无关。

（症状最初由 [#6305](https://github.com/deepseek-ai/deepseek-harness/discussions/6305) 的两位报告者复现。）

## 机制

发布版 `@deepseek-ai/dsh@0.1.5-rc.1` 的 `lib/bin.js` 末尾：

```js
if (import.meta.main) await runCli();
```

`import.meta.main` 是较新的 Node API，旧版本上是 `undefined` → 条件恒假 → **整个 CLI 主体从不执行** → 零输出、退出码 0、所有子命令一致。

同一台机器、同一份发布版 `bin.js`，实测：

```
Node v20.20.2: import.meta.main = undefined  → dsh --version: （空输出） 退出码 0
Node v22.17.0: import.meta.main = undefined  → dsh --version: （空输出） 退出码 0
Node v24.20.0: import.meta.main = boolean    → dsh --version: 0.1.5-rc.1
```

而**发布的 `package.json` 没有 `engines` 字段**（monorepo 根声明的是 `^22.19.0 || >=24.0.0`）→ npm 安装时不警告、不拒绝，用户完全无从察觉。

## 处置

**用户侧**：把 Node 升到 **22.18+** 或 **24 LTS** 即可，不需要重装 dsh。先确认两件事：

```bash
node -v                 # 是否 < 22.18（或 23.x）
dsh --version; echo $?  # 是否零输出且退出码 0
```

**上游侧（两点建议）**：
1. 给**发布的** `package.json` 补 `engines`（把 monorepo 根已有的 `^22.19.0 || >=24.0.0` 带下去就够），让 npm 在安装期就警告；
2. 入口不要依赖 `import.meta.main`（或加显式守卫 + 明确报错），避免旧 Node 上出现"安装成功但完全静默"这种最难排查的形态。

## 离线自查

`npx @moonquake2004/dsh-doctor --env --json` —— 其中 **E3-node** 会把 PATH 上的 node 与 `^22.19.0 || >=24.0.0` 比对并**最先报红**；**E1-node** 查 node 是否在 PATH；目录检查 **E7** 查 `dsh` 是否在 PATH。这类"命令存在但不可用"的环境问题，正是离线检查能在启动前拦下的。
