# 缺陷台账（让"自我进化"可度量）

> 目的：把"我能不能自己发现问题"从感觉变成**数字**。
> 关键指标是 **预发布发现率** = 发布前发现的缺陷 ÷ 全部缺陷。外部报告按定义都是**发布后**才来的。
>
> 台账的用法：若某段时间外部报告占比回升，说明内部预言机（红队 / 变异 / 边界枚举 / 上游推导）失明，
> 而不是"运气不好"。

## 来源分类

| 代号 | 含义 |
|---|---|
| **EXT** | 外部社区报告（用户/他人发现，发布后） |
| **RT** | 红队（自造的 fresh-context 对抗者，发布前） |
| **MUT** | 变异测试（破坏守卫，看测试是否变红） |
| **AUDIT** | 自审/回归审计/语料扫描（发布前） |

### 诚实的注解

1. **红队那 6 条，是因为用户要求才跑的。** 写进台账的当天，它还不是"默认动作"——
   `scripts/release-check.sh` 现在会强制要求本版本留下红队档案，**这才是把比率变成能力的机制**。
2. **纯内省（不借外部报告、不借自造对抗者、不借变异）找到的**，主要是**元问题与我自己引入的回归**（7 条）。
   实质缺陷几乎全部来自"不经过我模型的判断"——**这是这份台账最该记住的一条**。
3. 未修项（#5、#13、#14、#15）**在台账里保持可见**，不算"已解决"。
